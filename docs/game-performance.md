# macOS 游戏性能补丁

2026-09-30，在本机 M4、网易开发游戏 `3.8.0.313229` x64 上完成了上传瓶颈定位、运行时注入与 60 Hz 帧调度测试。客户端默认对受支持版本启用。“开发 → 测试设置”现在分别提供“图形性能优化”和“限制 60 帧”：关闭限帧可继续优化上传，不使用补丁的 60 Hz 等待；关闭优化后重启即可回退到普通渲染。其他版本继续支持下载和共存，不套用未知地址。

## 测量结果

用户报告原场景 30–40 FPS、1470×833、6 区块。探针实际读取的 OpenGL viewport 为 1470×825，未修改画质、渲染距离或模组选择。比较来自同一个游戏进程；没有固定相机回放，场景活动和其他系统负载会影响数值。

| 首轮基线 | 660 | 30.6 | 32.64 ms | 52.83 ms | 未作为首轮指标记录 |

最后一组超过 18 ms 的帧占约 0.46%，所以“稳定 60”指该测试窗口的大多数帧稳定在 16.67 ms，不能承诺任何场景都没有偶发长帧。去除初始 120 帧后计算分位数。独立的客户端候选 DLL 另连续记录了 40,920 帧，平均约 59.93 FPS，平均上传耗时约 0.73 ms/帧。最终增加了其他缓冲修改路径的失效保护，并完成了下述生产启动链路冷启动测试；人工移动、放置、画面和保存回归仍需确认。

2026-10-01，使用生产 `NativeDevelopmentLauncher` 与最终 Release 中的补丁资源，在独立游戏/容器快照完成正常登录、模组装配、自动注入和“已生效”状态验证。为避免两个游戏争用 GPU，短暂暂停旧进程；退出隔离测试后自动恢复旧进程，原项目选择文件 SHA-256 未变。去除初始 1,200 帧后，连续 3,600 帧平均 **59.94 FPS / 16.683 ms**。新窗口实际 viewport 为 **1470×801**，与原进程 1470×825 不同，因此这次用来确认最终补丁可自动加载并维持约 60 帧，不能充当完全同分辨率的 A/B 对比。

该记录位于 `analysis/performance/cold-start/result.json` 与隔离目录的性能日志。另保留了两个游戏和全套测试并行时的记录 `concurrent-load-result.json`（平均约 34.84 FPS）；它反映并行负载，未计入单游戏的性能结论。

### 独立限帧开关的验证

2026-10-01 最初候选同时设置游戏自己的 `gfx_max_framerate:60` 和补丁的 60 Hz 调度，并强制 swap interval 为 0。后续排查还尝试开启 VSync，用户实测仍为 30–40 FPS，独立测量约 30.41 FPS，未通过 58 FPS 的回归门槛。

随后从 9 月 30 日的执行记录完整恢复原源码；重新构建后，DLL 与此前实机验证的 `0e8cfb…` 文件 SHA-256 完全一致。渲染和缓冲代码回到原已验证版本。启动设置则改成只使用一套帧率时钟：启用受支持 DLL 时，游戏自己的上限设为 0，60 Hz 由 DLL 调度；普通渲染使用游戏内 60 帧上限。关闭限帧后两者均不设上限。两种模式均关闭 VSync；此前验证记录的原始 swap interval 也是 0。游戏画质、渲染距离和模组不变。实机统计仅采纳有缓冲上传的窗口，排除加载和退出期间的数百至数千 FPS 空画面。

在从用户原始 3.8 容器复制的新隔离副本中，最初候选 Release 的不限帧状态已确认是 `false`，游戏选项为 0；早期世界渲染窗口达到 121.07 FPS，预热后 3,600 帧平均 59.90 FPS，viewport 为 1470×810。这证明取消了启动器上限，但当前场景的持续速度仍受系统状态和渲染负载影响，不能将它称为固定 90 FPS。限帧测试则确认状态为 `true`；一次 3,600 帧平均 54.78 FPS，未达到额外设定的 58 FPS 下限。该失败结果保留在 `/tmp/mcdev-live-capped-final.log`，不能替换或隐藏历史稳定 60 的适用范围。用户随后观察到 20–40 FPS；这次回归不能视为通过，须以修正后的独立实机结果继续验证。

WGL 观察器另确认游戏请求的 swap interval 为 0；加入额外 GL 钩子后的测量约 34.31 FPS，属于有观察开销的诊断运行，单独保存为 `analysis/performance/frame-settings/result-unlimited-with-observer.json`，不用于游戏性能结论。干净运行的结果与对应日志另行保留。

这些自动测试验证启动链路、设置和实际呈现 cadence；本轮尚未完成优化后的人工移动、方块交互和保存回归。较新游戏打开的隔离存档与 3.8 性能回归容器已分开，原始项目选择与用户存档未受实验影响。

本地实验记录位于 `/Library/Afolder/WineProject/MCS/analysis/performance/`，包括 `baseline-initial-660.csv`、`baseline-upload.csv`、`ab-verified-pace.csv` 与 `production-run/performance.log`。运行时内存转储仅供本地分析，不打包或上传。

## 实际瓶颈与探针审计

游戏使用 OpenGL，macOS 驱动为 AppleMetalOpenGLRenderer。首轮 Windows 线程采样中，主线程 590/1000 次落在 Wine 的 `glBufferSubData`；后续按调用计时，平均约 19–20 ms/帧消耗在这一上传路径。每帧约 19 次写入同一个 1 MiB 顶点缓冲，数据量约 140 KiB，更新已被 GPU 使用的存储导致等待。

运行时能看到 ProfilerLite、MicroProfile 与 Tracy。ProfilerLite 的 tick 实测约 0.003 ms/帧；Tracy Profiler 1000 次采样中，995 次停在等待对象，Tracy DXT1 1000 次均停在延时等待。`glGetError` 与 `glFinish` 在所测渲染期间没有调用。现有启动器本来就设置 `WINEDEBUG=-all`。这些证据不支持把全部损失归于日志或探针。

没有把已有机器码“切换成 O2”，也没有绕过游戏打包、登录或校验。游戏本身包含优化后的寄存器/SIMD 代码以及开发诊断路径；缺少源码与构建选项时，不能将整个 EXE 重新优化编译。补丁针对测得的缓冲同步瓶颈，保留开发日志和模组诊断。

## 注入方式与数据完整性

1. 启动器流式校验官方游戏 EXE 的 SHA-256，只接受已测试的 `3.8.0.313229`。
2. 从应用资源解出约 49 KiB 的 Windows 注入器与 DLL，检查各自 SHA-256；不附带游戏或 Wine。
3. 游戏按正常登录、模组配置与 Wine 流程启动。注入器最多等待 10 秒让 Wine 注册进程，核对进程完整路径，再等待原程序完成初始化；读取受支持代码签名与 OpenGL 函数表后才加载 DLL。
4. DLL 再次核对代码和 Wine 11 函数地址，通过 MinHook 安装可回退的运行时钩子。只优化已确认的 1 MiB streaming array buffer，先回读完整内容，再更新 CPU 镜像并用新存储提交相同内容。
5. BufferData、删除、映射、复制、变换反馈和上下文切换会使镜像失效，下一次写入先重新读取；未知尺寸和其他缓冲走原始调用。仅首个呈现线程维护镜像、帧统计与限帧截止时间，其他呈现线程调用原函数。实验探针每 120 帧回读验证，未发现镜像与 GPU 数据差异。
6. 仅“限制 60 帧”开启时，提交完成后用 QPC 校准 60 Hz 截止时间。关闭后直接呈现，不等待 60 Hz 截止时间。没有关闭错误检查、缩减渲染距离或改变游戏规则。

Wine 的毫秒 Sleep 在测试中引入较大帧抖动，最终调度采用截止时间内短暂等待。它会增加主线程 CPU 使用和能耗，需要以实际机器的温度与长时间表现评估；关闭“限制 60 帧”可取消这一等待，并保留上传优化。

补丁失败时保留正常渲染，加载器超时只结束自己的辅助进程，不结束游戏或 wineserver；游戏退出会取消尚在等待的注入器。版本或 EXE 摘要不匹配时拒绝修改，用户可关闭优化启动。游戏 EXE、存档与模组源目录不被补丁改写。

性能摘要写入开发目录 `logs/performance-<时间戳>.log`，每 120 帧记录 FPS、平均/P95/P99 帧时间、上传时间和实际 viewport，可通过现有日志弹窗筛选、复制和导出。日志不记录账号、场景内容或内存数据。

冷启动时发现 Wine 后台进程可能继承注入器输出管道，即使注入器已成功退出也没有 EOF。启动器现在以注入器退出码判断加载结果，并取消自己的管道订阅；不再把 EOF 等待超时误报为注入失败。回归测试覆盖了辅助进程成功退出但后台任务仍持有管道的情形。

## 源码与构建

- `lib/development/performance_patch*.dart`：摘要、资源安装和辅助进程管理。
- `tools/performance/native/graphics_patch.c`：图形优化、数据失效保护与帧调度。
- `tools/performance/native/inject.c`：进程路径与运行时布局核对，等待后注入。
- `tools/performance/minhook/`：MinHook v1.3.4，来源 commit `c3fcafdc10146beb5919319d0683e44e3c30d537`，保留 BSD 许可证。

安装 MinGW 开发工具后执行 `python3 tools/performance/build.py`。该脚本使用 `-O2`、不写入 PE 构建时间戳，输出两份小型 x64 PE；变更源码后必须同步 `performance_patch.dart` 的摘要并运行相关测试，再构建 Flutter macOS Release。

后续版本须重新取得 EXE 摘要、解包后的代码布局与 OpenGL 表，并重复相同场景帧时间、GPU 数据一致性和实际游玩测试，不能仅修改版本号。
