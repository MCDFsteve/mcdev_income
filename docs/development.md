# Windows / Apple 芯片 Mac 本地模组开发

“开发”页面提供开发数据路径管理、按需下载游戏、导入本地模组及启动测试世界。界面使用现有 Flutter 和 OreUI；账号共用软件已有的登录流程，测试时只启动游戏，无须启动 MCS 编辑器。入口在 Windows 和 Apple 芯片 macOS 显示，Mac 在 Rosetta 下运行客户端时也能识别。Windows 直接运行官方 `Minecraft.Windows.exe`，不安装 Wine、DXMT 或 macOS 窗口组件。

## 平台模块与窗口管理

- `lib/desktop/window_controller.dart`：管理器在 Windows、macOS、Linux 上统一使用 `window_manager` 初始化无系统标题栏的窗口、拖动、最大化、最小化和关闭；安卓及 Web 不调用桌面插件。Mac 保留系统红绿灯，Windows / Linux 使用 OreUI 窗口按钮。Mac 管理器原有的 Swift 拖动层和窗口操作通道已移除。
- `lib/development/platform/game_runtime_io.dart`：每个测试页的运行环境接口，负责准备目录、路径转换、进程环境、启动和退出。`windows_game_runtime.dart` 与 `macos_game_runtime.dart` 提供实现，`runtime_factory_io.dart` 是后端选择入口。
- `GameWindowBackend`：统一的游戏窗口准备、附着、关闭及诊断接口。Mac 后端装配 Wine 应用身份和原有 Cocoa 游戏顶栏；Windows 后端启动独立 Flutter 宿主，由 `window_manager` 管理窗口，Win32 适配器只负责验证进程身份并嵌入游戏 HWND。共用 OreUI 顶栏，游戏图标来自同一 Bedrock 图标源。
- `GameChromeBackend` / `WindowController`：顶栏只面向接口调用；平台工厂选择窗口操作、原生菜单与按钮样式。`GameDiagnostics` 提供运行环境事件，公共启动器不读取平台专属目录。
- `development_capabilities.dart`：界面按后端能力显示设置。Windows 隐藏 Wine 安装、Mac 图形补丁、Metal 适配和 Command + Shift 设置，保留游戏本身的渲染器选择、限帧和模组功能。
- `host_files_io.dart`：平台文件操作。Windows 使用系统 `robocopy` 并行复制，Mac 使用 `ditto`；独立游戏准备优先使用 APFS 克隆。迁移保持逐文件校验，Windows 的临时会话锁不复制。
- `game_archive_io.dart`：统一进行归档路径检查、解压及官方文件清单校验。游戏包的外层构建目录在解压时移除，Windows 文件遍历使用扩展路径，避免长路径被误报为目录不可读。
- 公共启动器继续负责官方清单与下载、账号、游戏校验、模组装配、世界配置及日志。Windows 的 LAN 注入辅助程序由 CMake 随应用编译，按 PID 和完整路径验证目标；退出也只针对当前测试页的进程。

Linux 和安卓的游戏启动后端尚未启用。后续适配在运行环境工厂中增加实现及能力声明，下载、项目管理与界面无需各自添加系统判断。独立游戏进程的 macOS 嵌入式顶栏仍通过 `WindowController` 的游戏窗口适配器控制其所属 Wine 窗口；它不属于管理器的主窗口。

## Windows 数据与验证

默认开发目录为 `%LOCALAPPDATA%\mcdev_income\development`。每个测试页在 `prefixes/game[-<会话ID>]/` 下保存独立游戏副本、`users/Developer/AppData/Roaming/MinecraftPE_Netease/` 游戏数据和 `MCDevTests/` 启动配置。旧版 `profile/` 会在首次启动时整体迁移到 `users/Developer/`，保留存档；新旧目录同时存在时报告冲突，不覆盖数据。

Windows 后端为运行中的会话分配一个未占用的虚拟盘符，游戏看到标准层级的 `X:\users\Developer\AppData\Roaming`，文件仍在所选开发目录中。这样可兼容网易 Python 加载器对用户目录层级的假设，避免把隔离目录误拼进模块名。子进程环境和游戏路径由后端统一转换。退出时仅移除指向该会话的映射；异常退出后下次启动复用该会话的原映射。多个测试页独占不同盘符，盘符耗尽时会明确提示。系统环境、用户的真实 AppData 和网易启动器目录不被修改。

下载流程与 Mac 相同：查询官方完整清单，按用户选定版本下载并验证全部游戏文件。不会自动使用本机 MCStudio 安装，也不包含开发机上的固定路径。首次启动要复制独立游戏文件，耗时与磁盘速度、文件数量有关；后续启动复用此副本。

安装重试复用已完整下载的 ZIP，仍按最新官方补丁清单逐文件校验。损坏的压缩包缓存会失效，下一次重试重新下载；磁盘或权限错误保留缓存，并显示失败阶段、系统错误和路径。

Windows 实机烟雾测试（显式启用，复制到 `build/windows-runtime-smoke`，不读取登录凭证）：

```powershell
$env:MCDEV_WINDOWS_GAME = '你的开发版游戏目录\3.10.0.420447'
flutter test test/live_windows_runtime.dart
```

该测试检查真实游戏启动、在隔离目录创建数据以及正常请求退出，不代表登录后的世界、皮肤或多人联机均已实机验收。

## 首次使用

1. 使用软件已有的“设置”登录开发者账号。
2. 打开“开发”，自动创建默认开发目录并显示游戏版本、项目和测试入口；可在“管理目录”中改用其他位置。已有目录异常或保存的位置不可访问时会保留原设置，显示恢复入口。
3. Mac 点击“下载 Wine 与启动补丁”。Wine 11.0_1 压缩包约 185 MB，下载后自动校验、解压和应用兼容补丁，需要已安装 Rosetta 2。Windows 跳过此步。
4. 点击“浏览可下载版本”，按版本号、架构和渠道查找需要的游戏版本，然后安装。客户端实时读取官方完整清单，校验补丁清单及每个游戏文件后才完成安装。
5. 导入项目文件夹或 `.mcpack`、`.mcaddon`、ZIP 归档，勾选要测试的项目。同一项目的行为包与资源包合成一项，一起启用。
6. 在顶部“启动游戏”区域选择一个已安装版本，直接填写世界名称、选择生存或创造，然后点击“启动测试”。测试前会重新读取并复制所选包的最新文件。
7. 首页“使用新存档”默认不勾选，继续最近一次创建的测试存档。勾选后每次启动都会创建独立的新存档，并显示“世界种子”输入框，留空为随机种子。取消勾选后继续最近一次创建成功的存档。游戏内使用“保存并退出”保留进度；修改世界名称不会单独创建存档。

首次下载和解压建议预留至少 15 GB 空间。下载缓存、解压暂存目录和最终安装会在部分阶段同时占用磁盘；安装后的占用取决于版本和测试世界大小。

“仅打开游戏主菜单”适合检查运行环境。未勾选时，客户端按照所选包和世界配置直接启动本地测试。软件中的“退出测试”按钮先请求关闭游戏窗口，若进程未响应会结束本应用的独立 Wine 容器；保存操作应在游戏内完成。

## OreUI 窗口与 macOS 菜单

macOS 管理器和测试游戏使用 48pt 的 OreUI 自绘顶栏，隐藏系统标题和标题栏底色，保留系统红绿灯、窗口缩放及原生全屏。顶栏文字区域支持拖动和双击缩放，游戏顶栏右侧提供暂停 / 返回和全屏按钮。游戏全屏时隐藏顶栏，退出全屏后恢复；游戏内容区与顶栏分开，不覆盖 HUD。

测试游戏的 macOS 左上角菜单栏在 `lib/desktop/game_chrome.dart` 中使用 Flutter `PlatformMenuBar` 声明，包括暂停 / 返回、物品栏、聊天、输入命令、切换视角、显示 / 隐藏界面、F1–F12，以及最小化、缩放、全屏、隐藏和退出。声明通过专用 `mcdev_income/game_menu` 通道注册为原生菜单，菜单项直接绑定所属游戏窗口的原生动作，菜单收起后执行。功能键显示本地 3.10 / 3.8 逆向核对的默认功能名称并保留 F 编号，调试键和 RenderDoc 帧捕获注明使用条件；未发现默认单键功能的项也明确标注。按键仍原样传给当前游戏，实际执行取决于版本、上下文和自定义键位。映射与二进制依据见 [功能键说明](game-function-keys.md)。菜单属于测试游戏进程，切换到其他应用时跟随 macOS 正常切换。退出菜单与红色按钮均请求正常关闭游戏窗口；需要保存进度时先在游戏内保存。

窗口组件 `game-window-chrome.dylib` 仅加载到独立游戏应用的主 loader，复用当前客户端的 FlutterMacOS.framework 和 App.framework，并通过 `gameChromeMain` 入口绘制顶栏和注册菜单。游戏画面仍由原来的 Wine 图形路径绘制。按键通过游戏进程自身的事件队列投递，不使用全系统键盘模拟，不需要额外辅助功能权限。组件按 SHA-256 校验并缓存在开发数据目录的 `runtimes/game-window-chrome-v1` 中，现有输入补丁与窗口组件同时加载。

2026-10-03 菜单修复：菜单操作在 AppKit 收起菜单后执行，游戏按键先恢复 Cocoa 和 Wine 焦点，再通过 Wine 的 `postKey:pressed:modifiers:event:` 投递。合成 `NSEvent` 的键盘类型为 0；直接调用 `postKeyEvent:` 会让 Wine 切换布局并发送 `WM_CANCELMODE`。新路径保留实际键盘布局。`python3 tools/windowing/test.py` 覆盖此问题及原生菜单目标、参数、快捷键和分隔线；4 项 Flutter 测试覆盖全部 25 项动作绑定及组件缓存校验。Release 构建通过。实机自动化遇到焦点切换和窗口读取超时，本轮未将全部菜单项的游戏效果标为验收通过。修改后需要重启管理器并重新启动测试游戏，才能加载新组件。

修改原生窗口代码后运行 `python3 tools/windowing/build.py`，只编译此窗口组件并同步 Dart 校验值，再执行 `flutter build macos --release`。正式游戏启动需要完整的 macOS 应用包；隔离测试可通过 `MCDEV_CHROME_CLIENT_APP` 指定构建后的客户端。`tools/windowing/native/probe.m` 是不依赖游戏或登录的 Cocoa 验证窗口，可用于检查顶栏几何和功能键事件。

## 游戏窗口读取

测试应用使用国际版基岩版的官方草方块图标，来自 [Mojang AB 的 App Store 页面](https://apps.apple.com/us/app/id479516143)。原始 PNG、下载来源与 SHA-256 记录在 `assets/development/minecraft-bedrock-icon-source.json`；转换后的 ICNS 随启动器打包，并写入测试应用的 `Contents/Resources/MinecraftBedrock.icns` 和 `CFBundleIconFile`。现有管理缓存缺少图标或图标损坏时，下次启动自动重建并重新签名。

游戏主进程现在以正规的 macOS 应用“我的世界测试”运行。2026-10-01 已通过窗口操作工具直接读取 `3.10.0.420447` 的 RenderDragon/DXMT/Metal 世界画面、HUD、加载界面和暂停菜单，并用 Escape 切换菜单、点击游戏内“保存并退出”。独立存档中的 `3.8.0.313229` OpenGL 世界与内容日志也已成功读取，原图形补丁激活，生产启动与请求关窗测试通过。窗口读取不再依赖用户手动截图；灵动视效的彩色条带与拉伸仍存在，窗口修复不代表渲染修复完成。这轮没有进行前台帧率对比验收。

普通 `bin/wine` 会重新执行 `.app` 外的真实 loader，导致窗口缺少可识别的应用身份。启动器在所选 Wine runtime 内按需创建 `我的世界测试.app`，复制已校验的真实 x64 loader，设置应用标识并进行临时签名。仅游戏主进程使用 `WINELOADERNOEXEC=1` 跳过 bootstrap；Wine helper、注入器与 wineserver 沿用原命令及环境。游戏参数、登录、存档和图形补丁继续使用原流程。

应用包很小（本机签名后文件合计约 13 KB），库仍放在原 runtime，通过相对链接加载；开发目录迁移后无需重写绝对路径。创建前核对 loader SHA-256，启动前验证签名、应用标识和库链接；损坏缓存会重建，同名的非管理文件不会被覆盖。OpenGL 和 Metal 使用不同的应用标识。选择窗口时可按“我的世界测试”及窗口标题 Minecraft 识别。当前验证涵盖窗口工具的应用识别、画面读取和键盘操作，尚未逐个测试第三方会议软件的分享列表。

## 渲染器与帧率

“开发 → 启动游戏”直接提供以下设置：

- **渲染器**：3.9 及以上可选择 OpenGL 或渲染龙，按游戏版本分别保存。旧版本使用 OpenGL。此开关遵循 MCS 1.1.59.13193 的版本判断与 `render_engine` 枚举；测试世界配置另传入与所下载客户端相符的 `client_type`。
- **灵动视效（实验性）**：`3.10.0.420447` Haldra x64 选择渲染龙后可启用，使用独立 DXMT/Metal 运行环境，首次启动下载约 18 MB 组件。按版本保存，当前要求 macOS 14+；详见 [渲染龙与灵动视效](render-dragon.md)。
- **玩家皮肤**：可选史蒂夫（粗手臂）或艾利克斯（细手臂），默认史蒂夫，按测试页保存。公共启动器调用 `GameRuntime.prepareSkin`，由系统后端生成配置。Windows 直接使用 `skin: "steve" / "alex"` 和 `in_package: true` 选择官方内置皮肤，由皮肤包提供模型与身份；不传 PNG 导入专用的 `skin_iid`，否则客户端会把名称当作文件路径校验。Mac/Wine 保留 PNG 导入：将所选版本自带纹理原样复制到容器的 `C:\MCDevTests\skins\`，规避 `Application Support` 等含空格的路径；每次启动刷新，缺少纹理时报告错误，并写入 `slim`、`sync=true`、`in_package=false` 及 `skin_iid`（史蒂夫 `-1`、艾利克斯 `-2`）。官方 PNG 必须保留原始字节，重新编码可能触发客户端资源校验失败。仅打开主菜单时不应用测试皮肤。
- **图形性能优化**：目前只对已验证的 `3.8.0.313229` x64 OpenGL 启用缓冲上传补丁；不支持的版本或渲染路径隐藏此设置，保留已保存的优化偏好。
- **限制 60 帧**：默认开启；关闭后保留图形优化，并取消启动器的帧率上限。该偏好全局保存，游戏退出后修改、下次启动生效。60 是上限，实际速度仍取决于场景和硬件。
- **显示开发控制台**：与游戏“调试”中的同名选项一致，默认关闭。全局保存，启动前写入 `dev_showDevConsoleButton:0/1`，下次启动生效。
- **关闭我的伙伴**：默认勾选，按测试 Tab 保存，重启测试世界后生效；取消勾选可恢复伙伴。局域网测试玩家继承房主选择。“仅打开游戏主菜单”不传测试配置，因此该模式禁用此项。
- **Shift + Command 切换全屏**：默认关闭，避免 macOS 截图时触发游戏全屏切换。全局保存，重启游戏后生效。关闭时仅在游戏进程内屏蔽同时按下的 Command 与 Shift；单独使用这两个键仍有效，系统截图快捷键保留。开启时恢复 Wine 原本的组合键行为。

全屏快捷键使用独立、签名并校验 SHA-256 的小型 macOS 输入组件，按需缓存到 `runtimes/input-guard-v1/`。仅关闭快捷键时通过游戏 loader 的环境加载，不改写 Wine 或游戏文件，也不重建图形与性能补丁。源码及无系统输入的原生验证位于 `tools/input/`；可用 `python3 tools/input/build.py` 重建，重建后需同步 Dart 中的组件哈希。

## 下载与账号

客户端不附带游戏或 Wine，也不附带 MCS 登录 SDK、Wine 10 或 .NET 登录依赖。开发页面使用既有 Flutter 登录凭证，通过官方 `POST /users/refresh_mcs_user_token` 换取短期游戏访问令牌。该路径来自 MCS 的 `G79Http.QueryToken`，返回 `user_id`、`token` 和 `expired_at`；游戏服务请求直接使用该令牌，网站 Cookie 仅发送到开发者平台。

官方服务地址通过 `https://x19.update.netease.com/serverlist/experience.0.4.json` 获取，游戏清单接口为 `POST /interconn/web/pack-setting/get-for-mcstudio`，正文的 `setting_name` 为 `sdkclient_full_patchlist`。稳定渠道使用 `stable_x64`，完整列表读取 `entities`，安装由用户选择。2026 年 9 月 30 日本机实测稳定指针返回 `3.8.0.313229`，完整列表同时包含 3.10，不能把稳定指针当成唯一可用版本或最新数值版本。

游戏使用官方 CDN 下载。清单中的 MD5 对应 `patch.json`，随后按其中的 MD5 清单验证完整游戏目录，未列出的文件从安装暂存目录移除。Wine 使用固定版本和 SHA256 校验，依次尝试上游 GitHub、gh-proxy.com、ghfast.top。后两者是下载代理，不是大学镜像。未采用依赖 `/opt/local` 的 MacPorts 镜像包。

“游戏版本管理”分为“已安装”和“可下载”两个视图。可下载视图列出官方 `entities` 中具有有效下载描述的全部数值版本，按版本号排序；默认筛选 x64，也可切换全部架构或 x86。稳定、预览、Beta 和测试标签分别来自 `stable[_x64]`、`stable_new[_x64]`、`beta[_x64]`、`test[_x64]`，也识别对应的 `*_haldra_x64` 指针。未被渠道指针标记的包显示为“其他版本”。Haldra 包显示“渲染龙客户端”。`PCLauncher` 等别名是启动器构建，不作为数值游戏版本列出。

2026 年 9 月 30 日实测有 249 个数值游戏版本，其中 x64 59 个、x86 190 个；清单包含 `3.10.0.420447`，当前 x64 稳定指针为 `3.8.0.313229`，Beta 为 `3.8.0.274326`，没有 x64 测试渠道指针。3.10 与 Beta 的补丁清单 HEAD 请求均成功。客户端列出清单实际存在的版本，不凭空构造测试版本。安装时重新查询并下载用户指定的版本，若已被官方移除则报告错误，不替换成稳定版。

每个版本保存在独立的 `games/<version>/` 目录。安装或导入新版本不会覆盖其他版本，也不会改变已选择的启动版本；首次安装时自动选择唯一可用版本。在启动区的版本选择器或管理弹窗中选择一个版本后，该选择会保存并在重启后恢复。游戏文件共存。同一测试 Tab 的不同版本沿用该 Tab 的容器与存档；不同 Tab 的运行容器和存档互相隔离。

游戏访问令牌只保留在当前启动器内存中；账号变更或退出后，下次操作重新读取现有登录。开发页面不增加第二套账号登录或密码保存流程。

## 模组支持范围

支持具有 `manifest.json` 的资源包、行为包和脚本包，以及包含这些包的归档。导入文件夹时保留原项目，测试前重新同步；移除列表条目不会删除源项目。UUID 和版本用于识别包，勾选状态与游戏版本选择会保存。

“本地项目”标题右侧的排序图标打开排序弹窗，可按导入时间、最近一次启动时间或名称字母正反排序，默认最近导入在前。排序方式按测试 Tab 保存，游戏运行时也可调整。导入时间记录首次登记，重新导入保留原时间；启动时间在启动所选项目的测试游戏后记录，仅打开主菜单或加入局域网不会改写。行为包与资源包作为一个项目排序，未启动过的项目在启动时间排序中始终置后；升级前没有时间记录的项目按原登记顺序回退，之后开始积累启动记录。名称排序忽略英文字母大小写，中文按字符顺序排列。

主列表以项目显示，行为包与资源包一起勾选、一起移除。勾选框与项目标题之间显示 40 像素的模组图标，优先读取行为包的 `pack_icon.png`，缺失或无法解码时依次尝试同项目的其他包；均不可用时显示占位图标。点击图标与点击标题一样统一勾选项目。项目标题取自 `manifest.json` 的 `header.name`，移除 Minecraft 格式代码及前后空格；同一项目的包标题不同时优先使用行为 / 脚本包标题，没有有效标题才使用文件夹名。刷新时重新读取源文件中的标题，源目录暂时不可用或文件正在编辑时保留登记名称。项目旁的详情图标打开弹窗，查看每个包各自的标题、类型、版本、路径及 UUID；“移除项目”也在此弹窗内。已有登记按同一父目录与去掉 Minecraft 格式代码、末尾空格的名称合并，不合并不同目录下的同名项目。新导入记录项目目录，因此同一项目内不同名称的包也能一起显示。旧记录若仅启用一部分包，会显示“部分启用”，点击项目后统一启用全部包。

启动游戏区域放在页面顶部，突出版本选择与启动按钮；世界名称、游戏模式、皮肤、渲染器和全部开关直接显示，按内容宽度流式排列，空间不足自动换行，详细说明保留为悬停提示。版本管理统一由下方“游戏版本”区域进入。内容可用宽度达到 720 逻辑像素时，其下使用两列：左侧管理目录、Wine 和游戏版本，右侧项目列表；文字放大时相应提高所需宽度。桌面两列始终各自独立滚动，滚动本地项目不会移动左侧、启动区或状态栏。较矮窗口限制启动卡片的最大高度，过高的启动设置仅在该区域内滚动；项目区高度不足时仅在右列内滚动整张项目卡片。仅宽度不足时改为单列滚动。底部状态栏始终保留同样高度，启动、下载进度、提示和错误不会挤压主体；长消息可打开“运行详情”。调整内容布局不会重建启动器或清空测试世界名称。

“查看日志”打开独立日志弹窗，默认打开本次测试的“模组”日志，否则优先打开最近的历史测试日志。新测试日志只写入所选模组自己的 `print`、能追溯到模组的脚本错误堆栈和资源加载错误；Wine、网易框架、图形补丁及启动器局域网辅助包的输出不写入测试日志。中文、多行输出和看起来像引擎日志的模组 `print` 保持原样。历史日志保持原有内容；渲染、性能等诊断文件仍可在来源下拉框中手动查看。弹窗每 750 毫秒检查新增内容，使用增量 UTF-8 解码保留跨读取边界的中文和未结束行；日志缩短时重新加载。

模组日志使用 MCS 的 `loggingIP` / `loggingPort` 本地通道。启动器只在所选包的装配副本中为 Python 脚本包加入来源标记，不修改原项目；原始 `__init__.py` 独立编译执行，保留编码、文档字符串、`__future__` 和行号。每个游戏、每条日志连接单独解码与筛选，局域网玩家复制房主副本时会恢复原始初始化代码，再安装自己的标记。原生资源错误需要引用所选包、文件或声明的内容标识才能归入模组日志，不按“所有 ERROR”放行框架错误。

日志使用等宽字体，并对错误、警告、信息、调试级别以及时间、路径、JSON 键、字符串、数值和代码关键词高亮。关键词筛选不区分大小写，可与级别筛选组合；堆栈续行保留上一条诊断的级别。默认自动滚动，向上滚动或关闭复选框后暂停跟随，新内容仍继续接收；重新勾选或点击跳到最新图标可恢复。支持拖选文本、复制单行、复制筛选结果、导出筛选结果与导出原始日志。macOS 日志导出使用归属本应用窗口的原生保存面板选择路径，取消后不写文件，失败会在弹窗显示。

首次打开大日志读取末尾 512 KiB，显示缓冲区最多保留 5,000 行或约 2 MiB 文本，避免大量 Wine 输出拖慢界面。截断时显示说明，筛选、复制和筛选导出均作用于已加载内容；原始导出保留完整文件，并固定导出开始时的文件长度。导出禁止覆盖当前开发目录中的日志。弹窗只读取当前开发目录内的普通日志文件，关闭弹窗后停止轮询。

当前支持继续最近一次测试存档或创建新存档，暂未提供历史存档选择与删除界面。局域网多玩家测试见下文。尚未实现 MCS 的脚本断点调试、完整 RPC 控制、公网联机服务及可视化资源编辑。启动器不会自动补齐模组缺失的依赖，需要导入并勾选配套包。

## 兼容补丁与来源

Wine 游戏环境来自 [Gcenx macOS Wine builds 11.0_1](https://github.com/Gcenx/macOS_Wine_builds/releases/tag/11.0_1)。原始下载 SHA256 为 `b50dc50ec7f41d58b115a6b685d4d1315ba3c797bd3aa0f49213f2703cb82388`。

补丁实现位于 [`lib/development/wine_patch_io.dart`](../lib/development/wine_patch_io.dart)。它只接受指定原始文件哈希，修改 Wine 的 `winemac.so` 和 `opengl32.dll`，对修改后的 macOS 文件进行本机临时签名，并再次验证结果哈希。游戏可执行文件保持官方下载内容。未来 Wine 或游戏版本可能需要重新适配；新版本安装保留旧版本供回退。

对已测试的 `3.8.0.313229` x64，还提供默认启用的图形性能优化，60 帧上限为独立开关。它通过小型 DLL 在运行时优化缓冲上传，不改写游戏 EXE；其他版本继续使用普通启动流程。测量结果、适配范围、CPU 代价和验收状态见 [游戏性能补丁](game-performance.md)。

Wine 及随其发行的组件遵循各自上游许可证。Wine 源代码、许可证和构建资料可在 [WineHQ](https://gitlab.winehq.org/wine/wine) 和上述构建仓库查看。游戏版权及使用条件由网易和 Minecraft 官方规定，游戏文件从官方服务按需下载。

## 多开测试 Tab

开发页面的启动区现在使用可增删的标签页，至少保留一个。标签标题取当前勾选项目的签名标题，多个项目用 ` + ` 连接，未选项目时显示“原版测试”；长标题省略显示并提供完整提示。`+` 紧接标签列表，关闭按钮使用裸图标。启动按钮在左，版本选择在右，运行状态显示在对应标签上。

每个 Tab 独立保存模组选择、版本、渲染器、帧率限制、皮肤、控制台、全屏快捷键、新旧存档、种子及世界名称/游戏模式。关闭客户端后恢复标签顺序和当前页；数据迁移保留稳定的 Tab ID。第一个默认 Tab 继续使用 `prefixes/game/` 及原有存档，新 Tab 使用 `prefixes/game-<Tab ID>/`。取消新存档选项后继续该 Tab 最近一次创建成功的存档。关闭标签只移除页面记录，保留容器、存档和源项目。

游戏下载和 Wine 安装由所有 Tab 共享，下载/准备阶段串行保护共享资源；游戏运行期间释放共享锁，其他 Tab 可以继续配置、导入和启动。各实例拥有独立的 Wine 容器、RPC 端口、游戏配置、日志和游戏文件工作副本，退出操作只针对本实例。工作副本位于对应容器的 `mcdev-games/<version>/`；APFS 使用写时复制共享未改变的数据块，不支持克隆的磁盘回退为完整复制。安装目录不再承载每实例的 SDK 可写配置。

游戏的独立 macOS app、窗口标题、Dock 和菜单名称为“我的世界测试 · 项目标题”。关闭正在运行的 Tab 会先提示保存并请求该游戏退出。任一测试仍运行时，禁止迁移数据目录；跨进程文件锁也检查整个游戏生命周期，避免另一个客户端移动活跃容器。

## 每个测试页的局域网玩家

启动此页的测试世界后，“局域网测试”按钮在世界与本地监听端口就绪时启用。弹窗设置玩家名字及史蒂夫／艾利克斯，每次启动打开一个独立窗口，加入此页正在运行的世界。可以继续添加玩家，启动器不设置窗口数量上限；实际容量取决于游戏本身与机器资源。玩家名不能为空，UTF-8 编码长度最多 16 字节，例如最多 16 个 ASCII 字符或 5 个常用汉字；拒绝空白、控制字符及当前世界已占用的名字。按字节校验可避免游戏截断多字节字符后出现乱码和名单无法匹配。

添加访客后显示“玩家列表”。名单读取服务器脚本的实际玩家列表，区分启动中、已加入、已离开和失败；仅启动了进程不会显示为已加入。当前世界的其他玩家也会出现，但启动器只提供关闭自身管理窗口的操作。关闭一个访客不会退出房主或其他玩家；退出房主或关闭该测试页会关闭此页的访客，其他测试页不受影响。

访客继承房主的游戏版本、图形与测试设置，拥有独立 Wine 容器、日志、配置和 macOS 应用身份。窗口与 Dock 名称追加玩家名。模组从房主已经装配的副本同步，包括用于读取玩家名单的辅助行为包；运行期间修改源项目不会让后来的访客装入另一套模组。访客不创建或覆盖房主存档。每次访客启动前重新确认房主进程、世界实例和端口，避免旧世界或其他测试页端口被误用。名单刷新延迟或一次 UDP 回应丢失时，最多等待 12 秒重新验证；房主退出或切换世界则立即取消，不将临时未就绪误报为世界退出。

局域网兼容适配仅支持精确版本 `3.10.0.420447` Haldra x64；其他版本的按钮保持禁用并说明尚未适配，不因检测到端口而开放未验证的连接。`tools/lan/lan_patch.c` 与 `lan_patch_io.dart` 校验原始游戏及辅助 DLL 的 SHA-256，再检查运行时指令签名；仅修改内存，不改写下载的游戏。房主使用原生 RakNet 本地监听，访客使用匹配的本地封包格式。局域网角色由启动器显式传入，认证及入站消息校验保留。端口发现仅查询对应 PID 的 IPv4 UDP 回环／通配监听，并验证 RakNet 回应，不扫描局域网或其他进程。

测试启动沿用官方 MCS `CppGameOptionM.SetForceOptions()` 的 `resource_concatenation_enabled=0` 与 `dev_assertions_debug_break=0`。后者沿用官方关闭开发断言调试中断的选项，不代表原生资源断言被禁用，也不能证明缺失资源或模型初始化问题已经修复。每个访客同时写入自身的 `mp_username`，与实际进入世界的玩家名保持一致。读取旧 `options.txt` 时容忍游戏截断名字留下的不完整 UTF-8，保留其他设置并用新名字覆盖旧值，避免旧访客容器无法再次启动。

独立访客使用 `multiplayer_game_type=100` 与房主地址进入远程世界，`room_info.muiltClient` 保持 `false`。设置 `muiltClient=true` 会选择 MCS 的快捷连接分支，跳过正常玩家、皮肤与公共资源初始化，不适用于这里的独立游戏进程。

名单辅助包每 30 个服务器 tick 写一次带启动标记、世界实例与序号的报告。启动器拒绝不完整、过期或不匹配的报告；超过 10 秒未刷新时不再认定玩家在线。旧版 RPC 端口回报不作为加入依据。适配源码事务测试覆盖签名不匹配、保护与指令缓存失败的回滚；`test/live_lan_smoke.dart` 是显式启用、使用独立诊断存档的实机验收入口。
