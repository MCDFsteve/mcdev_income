# Apple 芯片 Mac 本地模组开发

“开发”页面提供开发数据路径管理、按需下载 Wine 和游戏、导入本地模组及启动测试世界。界面使用现有 Flutter 和 OreUI；账号共用软件已有的登录流程，测试时只启动游戏，无须启动 MCS 编辑器。开发入口仅在 Apple 芯片 macOS 显示，在 Rosetta 下运行客户端时也能识别。

## 首次使用

1. 使用软件已有的“设置”登录开发者账号。
2. 打开“开发”，创建默认开发目录，或选择一个新的空目录。
3. 点击“下载 Wine 与启动补丁”。Wine 11.0_1 压缩包约 185 MB，下载后自动校验、解压和应用兼容补丁。运行 Wine 需要 Mac 已安装 Rosetta 2。
4. 点击“浏览可下载版本”，按版本号、架构和渠道查找需要的游戏版本，然后安装。客户端实时读取官方完整清单，校验补丁清单及每个游戏文件后才完成安装。
5. 导入项目文件夹或 `.mcpack`、`.mcaddon`、ZIP 归档，勾选要测试的项目。同一项目的行为包与资源包合成一项，一起启用。
6. 在顶部“启动游戏”区域选择一个已安装版本，在“测试设置”中填写世界名称、选择生存或创造，然后点击“启动测试”。测试前会重新读取并复制所选包的最新文件。
7. 在游戏中测试，使用游戏内的“保存并退出”保留进度。再次启动会打开同一个测试存档；修改名称不会新建另一个存档。

首次下载和解压建议预留至少 15 GB 空间。下载缓存、解压暂存目录和最终安装会在部分阶段同时占用磁盘；安装后的占用取决于版本和测试世界大小。

“仅打开游戏主菜单”适合检查运行环境。未勾选时，客户端按照所选包和世界配置直接启动本地测试。软件中的“退出测试”按钮先请求关闭游戏窗口，若进程未响应会结束本应用的独立 Wine 容器；保存操作应在游戏内完成。

## 游戏窗口读取

测试应用使用国际版基岩版的官方草方块图标，来自 [Mojang AB 的 App Store 页面](https://apps.apple.com/us/app/id479516143)。原始 PNG、下载来源与 SHA-256 记录在 `assets/development/minecraft-bedrock-icon-source.json`；转换后的 ICNS 随启动器打包，并写入测试应用的 `Contents/Resources/MinecraftBedrock.icns` 和 `CFBundleIconFile`。现有管理缓存缺少图标或图标损坏时，下次启动自动重建并重新签名。

游戏主进程现在以正规的 macOS 应用“我的世界测试”运行。2026-10-01 已通过窗口操作工具直接读取 `3.10.0.420447` 的 RenderDragon/DXMT/Metal 世界画面、HUD、加载界面和暂停菜单，并用 Escape 切换菜单、点击游戏内“保存并退出”。独立存档中的 `3.8.0.313229` OpenGL 世界与内容日志也已成功读取，原图形补丁激活，生产启动与请求关窗测试通过。窗口读取不再依赖用户手动截图；灵动视效的彩色条带与拉伸仍存在，窗口修复不代表渲染修复完成。这轮没有进行前台帧率对比验收。

普通 `bin/wine` 会重新执行 `.app` 外的真实 loader，导致窗口缺少可识别的应用身份。启动器在所选 Wine runtime 内按需创建 `我的世界测试.app`，复制已校验的真实 x64 loader，设置应用标识并进行临时签名。仅游戏主进程使用 `WINELOADERNOEXEC=1` 跳过 bootstrap；Wine helper、注入器与 wineserver 沿用原命令及环境。游戏参数、登录、存档和图形补丁继续使用原流程。

应用包很小（本机签名后文件合计约 13 KB），库仍放在原 runtime，通过相对链接加载；开发目录迁移后无需重写绝对路径。创建前核对 loader SHA-256，启动前验证签名、应用标识和库链接；损坏缓存会重建，同名的非管理文件不会被覆盖。OpenGL 和 Metal 使用不同的应用标识。选择窗口时可按“我的世界测试”及窗口标题 Minecraft 识别。当前验证涵盖窗口工具的应用识别、画面读取和键盘操作，尚未逐个测试第三方会议软件的分享列表。

签名、缓存复用、损坏修复、含空格路径迁移与同名文件保护的实机测试使用已下载的 Wine loader，不读取账号、启动游戏或改动存档：

```sh
MCDEV_TEST_WINE_RUNTIME='/absolute/runtimes/wine-11.0_1-mcs-v1' \
  flutter test test/wine_game_app_test.dart
```

## 渲染器与帧率

“开发 → 测试设置”提供以下设置：

- **渲染器**：3.9 及以上可选择 OpenGL 或渲染龙，按游戏版本分别保存。旧版本使用 OpenGL。此开关遵循 MCS 1.1.59.13193 的版本判断与 `render_engine` 枚举；测试世界配置另传入与所下载客户端相符的 `client_type`。
- **灵动视效（实验性）**：`3.10.0.420447` Haldra x64 选择渲染龙后可启用，使用独立 DXMT/Metal 运行环境，首次启动下载约 18 MB 组件。按版本保存，当前要求 macOS 14+；详见 [渲染龙与灵动视效](render-dragon.md)。
- **玩家皮肤**：可选史蒂夫（粗手臂）或艾利克斯（细手臂），默认史蒂夫。全局保存，启动测试世界时使用所选版本自带的 `steve.png` 或 `alex.png`，同时写入 `slim`、`sync=true`、`in_package=false` 和 MCS 对应的 `skin_iid`（史蒂夫 `-1`、艾利克斯 `-2`），明确指定纹理、手臂模型与皮肤身份。3.10 渲染龙已在无模组对照和原模组组合中，通过游戏库存中的实际艾利克斯纹理与细手臂验收。仅打开主菜单时不应用测试皮肤。
- **图形性能优化**：目前只对已验证的 `3.8.0.313229` x64 OpenGL 启用缓冲上传补丁；不支持的版本或渲染路径隐藏此设置，保留已保存的优化偏好。
- **限制 60 帧**：默认开启；关闭后保留图形优化，并取消启动器的帧率上限。该偏好全局保存，游戏退出后修改、下次启动生效。60 是上限，实际速度仍取决于场景和硬件。
- **显示开发控制台**：与游戏“调试”中的同名选项一致，默认关闭。全局保存，启动前写入 `dev_showDevConsoleButton:0/1`，下次启动生效。
- **Shift + Command 切换全屏**：默认关闭，避免 macOS 截图时触发游戏全屏切换。全局保存，重启游戏后生效。关闭时仅在游戏进程内屏蔽同时按下的 Command 与 Shift；单独使用这两个键仍有效，系统截图快捷键保留。开启时恢复 Wine 原本的组合键行为。

全屏快捷键使用独立、签名并校验 SHA-256 的小型 macOS 输入组件，按需缓存到 `runtimes/input-guard-v1/`。仅关闭快捷键时通过游戏 loader 的环境加载，不改写 Wine 或游戏文件，也不重建图形与性能补丁。源码及无系统输入的原生验证位于 `tools/input/`；可用 `python3 tools/input/build.py` 重建，重建后需同步 Dart 中的组件哈希。

2026 年 10 月 2 日，在隔离存档实测关闭状态的 `3.10.0.420447` RenderDragon 与 `3.8.0.313229` OpenGL：分别发送 `Command+Shift+P` 和 `Shift+Command+P`，窗口保持标准窗口模式。3.10 开启后，同一组合键可进入全屏并再次恢复窗口。两种状态均通过生产启动与正常退出检查；3.8 使用 Release 包中的输入组件，原图形优化正常激活。原生测试覆盖左右修饰键、两种按下/释放顺序以及 Wine 逐个投递按键时的中间状态；相关 Flutter 测试 30 项通过，另 1 项签名迁移测试未启用，静态分析无问题。Release 已重启并检查开关可操作，最终恢复关闭状态。

启动前更新 `options.txt` 的 `gfx_max_framerate`、`gfx_ne_vsync`、`frame_pacing_enabled` 和 `dev_showDevConsoleButton`；渲染龙适配另临时设置其渲染选项，保留其他画质、渲染距离与未知选项。限帧只使用一套时钟：启用受支持性能 DLL 时，游戏内上限设为 0，由 DLL 调度 60 Hz；普通渲染时游戏内上限设为 60。不限帧时游戏内上限和 DLL 调度均关闭。两种模式均关闭 VSync，避免驱动同步与补丁调度叠加。启动提示说明当前模式，性能日志记录实际呈现帧时间。若 DLL 未激活，提示本次补丁限帧也未生效，用户可退出后关闭优化，以游戏内限帧启动。

MCS 在“仅打开主菜单”模式下不传测试配置；因此该模式使用游戏默认渲染器，并禁用渲染器选择。版本列表中的“渲染龙客户端”标识官方 Haldra 安装包，不代表所有渲染路径均已通过 Wine 实玩验证。

2026 年 10 月 1 日，`3.10.0.420447` Haldra x64 已打通 RenderDragon → D3D11 → DXMT → Metal，并在隔离测试世界实际执行灵动视效的官方 SM5 材质。此前 Vulkan 路径的 MSAA/着色器初始化问题由独立后端适配解决；正常关窗时的 BGFX shader 引用计数断言也已修复。现在可以直接读取游戏窗口，但真实世界仍有彩色条带和拉伸，画质与性能尚未通过验收。3.8 OpenGL 沿用已恢复并由用户确认的原补丁。详细证据与边界见 [渲染龙与灵动视效](render-dragon.md)。

## 数据位置与迁移

默认路径为 `~/Library/Application Support/mcdev_income/development/`。点击“开发数据目录”中的“管理目录”可选择新目录、使用已有目录或迁移数据，包括已连接的外置磁盘。

| 位置 | 内容 |
| --- | --- |
| `runtimes/` | 按版本隔离的 Wine 及启动补丁 |
| `games/` | 已校验的游戏版本，更新时保留旧版本 |
| `prefixes/game/` | 独立 Windows 容器、游戏设置和测试存档 |
| `downloads/` | 下载包、断点续传文件和补丁清单 |
| `logs/` | 测试启动日志及游戏错误日志 |
| `projects/` | 导入归档后保存的模组文件 |
| `projects.json` | 模组登记和勾选状态 |

测试存档位于 `prefixes/game/drive_c/users/<Windows 用户>/AppData/Roaming/MinecraftPE_Netease/minecraftWorlds/mcdev_test/`。选中的包复制到该用户的 `AppData/Roaming/MinecraftPE_Netease/games/com.netease/` 下。

“选择新目录”创建空的开发环境；“使用已有目录”只接受本应用创建且带有效目录标记的环境；“迁移数据”先复制并逐文件验证，再切换路径设置。迁移成功后仍保留原目录，便于检查和回退。游戏运行或安装期间禁止迁移。Wine 的盘符链接不会被递归遍历。

原有账号、主题及作品管理配置保留在原配置位置，迁移开发数据不会移动它们。文件夹模组引用原路径，迁移后仍在原位置编辑；导入归档属于开发目录，随数据一起迁移。

## 下载与账号

客户端不附带游戏或 Wine，也不附带 MCS 登录 SDK、Wine 10 或 .NET 登录依赖。开发页面使用既有 Flutter 登录凭证，通过官方 `POST /users/refresh_mcs_user_token` 换取短期游戏访问令牌。该路径来自 MCS 的 `G79Http.QueryToken`，返回 `user_id`、`token` 和 `expired_at`；游戏服务请求直接使用该令牌，网站 Cookie 仅发送到开发者平台。

官方服务地址通过 `https://x19.update.netease.com/serverlist/experience.0.4.json` 获取，游戏清单接口为 `POST /interconn/web/pack-setting/get-for-mcstudio`，正文的 `setting_name` 为 `sdkclient_full_patchlist`。稳定渠道使用 `stable_x64`，完整列表读取 `entities`，安装由用户选择。2026 年 9 月 30 日本机实测稳定指针返回 `3.8.0.313229`，完整列表同时包含 3.10，不能把稳定指针当成唯一可用版本或最新数值版本。

游戏使用官方 CDN 下载。清单中的 MD5 对应 `patch.json`，随后按其中的 MD5 清单验证完整游戏目录，未列出的文件从安装暂存目录移除。Wine 使用固定版本和 SHA256 校验，依次尝试上游 GitHub、gh-proxy.com、ghfast.top。后两者是下载代理，不是大学镜像。未采用依赖 `/opt/local` 的 MacPorts 镜像包。

“游戏版本管理”分为“已安装”和“可下载”两个视图。可下载视图列出官方 `entities` 中具有有效下载描述的全部数值版本，按版本号排序；默认筛选 x64，也可切换全部架构或 x86。稳定、预览、Beta 和测试标签分别来自 `stable[_x64]`、`stable_new[_x64]`、`beta[_x64]`、`test[_x64]`，也识别对应的 `*_haldra_x64` 指针。未被渠道指针标记的包显示为“其他版本”。Haldra 包显示“渲染龙客户端”。`PCLauncher` 等别名是启动器构建，不作为数值游戏版本列出。

2026 年 9 月 30 日实测有 249 个数值游戏版本，其中 x64 59 个、x86 190 个；清单包含 `3.10.0.420447`，当前 x64 稳定指针为 `3.8.0.313229`，Beta 为 `3.8.0.274326`，没有 x64 测试渠道指针。3.10 与 Beta 的补丁清单 HEAD 请求均成功。客户端列出清单实际存在的版本，不凭空构造测试版本。安装时重新查询并下载用户指定的版本，若已被官方移除则报告错误，不替换成稳定版。

每个版本保存在独立的 `games/<version>/` 目录。安装或导入新版本不会覆盖其他版本，也不会改变已选择的启动版本；首次安装时自动选择唯一可用版本。在启动区的版本选择器或管理弹窗中选择一个版本后，该选择会保存并在重启后恢复。游戏文件共存，现有单个测试存档和运行容器仍共用。

游戏访问令牌只保留在当前启动器内存中；账号变更或退出后，下次操作重新读取现有登录。开发页面不增加第二套账号登录或密码保存流程。

## 模组支持范围

支持具有 `manifest.json` 的资源包、行为包和脚本包，以及包含这些包的归档。导入文件夹时保留原项目，测试前重新同步；移除列表条目不会删除源项目。UUID 和版本用于识别包，勾选状态与游戏版本选择会保存。

主列表以项目显示，行为包与资源包一起勾选、一起移除。项目旁的详情图标打开弹窗，查看每个包的类型、版本、路径及 UUID；“移除项目”也在此弹窗内。已有登记按同一父目录与去掉 Minecraft 格式代码、末尾空格的名称合并，不合并不同目录下的同名项目。新导入记录项目目录，因此同一项目内不同名称的包也能一起显示。旧记录若仅启用一部分包，会显示“部分启用”，点击项目后统一启用全部包。

启动游戏区域固定放在桌面页面顶部，突出版本选择与启动按钮，测试配置收进“测试设置”。其下使用两列：左侧管理目录、Wine 和游戏版本，右侧项目列表独立滚动。底部状态栏始终保留同样高度，启动、下载进度、提示和错误不会挤压主体；长消息可打开“运行详情”。窄窗口、较矮窗口或较大的文字缩放使用内容滚动，启动区域排在内容最前，状态栏仍保留固定空间。调整窗口不会重建启动器或清空测试世界名称。

“查看日志”打开独立日志弹窗，启动前也可浏览开发目录中已有的 `.log` 文件。默认打开本次启动日志，否则使用最近修改的历史日志；渲染龙适配状态另记录在 `renderer-<时间戳>.log`；下拉选择器可切换 Wine 控制台与游戏错误日志。弹窗每 750 毫秒检查新增内容，使用增量 UTF-8 解码保留跨读取边界的中文和未结束行；日志缩短时重新加载。

日志使用等宽字体，并对错误、警告、信息、调试级别以及时间、路径、JSON 键、字符串、数值和代码关键词高亮。关键词筛选不区分大小写，可与级别筛选组合；堆栈续行保留上一条诊断的级别。默认自动滚动，向上滚动或关闭复选框后暂停跟随，新内容仍继续接收；重新勾选或点击跳到最新图标可恢复。支持拖选文本、复制单行、复制筛选结果、导出筛选结果与导出原始日志。macOS 日志导出使用归属本应用窗口的原生保存面板选择路径，取消后不写文件，失败会在弹窗显示。

首次打开大日志读取末尾 512 KiB，显示缓冲区最多保留 5,000 行或约 2 MiB 文本，避免大量 Wine 输出拖慢界面。截断时显示说明，筛选、复制和筛选导出均作用于已加载内容；原始导出保留完整文件，并固定导出开始时的文件长度。导出禁止覆盖当前开发目录中的日志。弹窗只读取当前开发目录内的普通日志文件，关闭弹窗后停止轮询。

当前提供单个本地测试存档。尚未实现 MCS 的脚本断点调试、完整 RPC 控制、多人测试、联机服务及可视化资源编辑。启动器不会自动补齐模组缺失的依赖，需要导入并勾选配套包。

## 兼容补丁与来源

Wine 游戏环境来自 [Gcenx macOS Wine builds 11.0_1](https://github.com/Gcenx/macOS_Wine_builds/releases/tag/11.0_1)。原始下载 SHA256 为 `b50dc50ec7f41d58b115a6b685d4d1315ba3c797bd3aa0f49213f2703cb82388`。

补丁实现位于 [`lib/development/wine_patch_io.dart`](../lib/development/wine_patch_io.dart)。它只接受指定原始文件哈希，修改 Wine 的 `winemac.so` 和 `opengl32.dll`，对修改后的 macOS 文件进行本机临时签名，并再次验证结果哈希。游戏可执行文件保持官方下载内容。未来 Wine 或游戏版本可能需要重新适配；新版本安装保留旧版本供回退。

对已测试的 `3.8.0.313229` x64，还提供默认启用的图形性能优化，60 帧上限为独立开关。它通过小型 DLL 在运行时优化缓冲上传，不改写游戏 EXE；其他版本继续使用普通启动流程。测量结果、适配范围、CPU 代价和验收状态见 [游戏性能补丁](game-performance.md)。

Wine 及随其发行的组件遵循各自上游许可证。Wine 源代码、许可证和构建资料可在 [WineHQ](https://gitlab.winehq.org/wine/wine) 和上述构建仓库查看。游戏版权及使用条件由网易和 Minecraft 官方规定，游戏文件从官方服务按需下载。

## 开发者验证命令

常规验证使用 `flutter test` 和 `flutter build macos --release`。真实下载、账号及游戏测试独立放在 `test/live_development_smoke.dart`，不包含在常规测试发现范围内。

```sh
# 使用本机现有登录查询真实游戏清单
MCDEV_LIVE_DEVELOPMENT=1 flutter test test/live_development_smoke.dart

# 只读取完整版本清单，并检查最新条目与 Beta 的补丁 URL
MCDEV_LIVE_DEVELOPMENT=1 flutter test test/live_development_catalog.dart

# 继续导入验证包并打开真实测试游戏，退出游戏后结束
MCDEV_LIVE_DEVELOPMENT=1 MCDEV_LIVE_LAUNCH=1 flutter test test/live_development_smoke.dart
```

这些命令使用本机开发目录和账号，须明确启用；测试程序不输出 Cookie、访问令牌或密码。
